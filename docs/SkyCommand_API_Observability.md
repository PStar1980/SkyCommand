# SkyCommand API Observability

SkyCommand records normalized HTTP request evidence in PostgreSQL so the Command Center can show persistent API traffic, errors, latency, and route pressure.

## Stored evidence

`core.api_request_telemetry` stores:

- occurrence time;
- HTTP method;
- normalized route template;
- HTTP status code;
- response duration in milliseconds;
- application code when known;
- authentication mode;
- request and response byte counts;
- bounded request/correlation ID.

## Privacy and cardinality boundary

The middleware deliberately does **not** store:

- authorization headers, bearer tokens, or internal service tokens;
- request or response bodies;
- raw query-string values;
- passwords, secrets, or form values;
- raw UUIDs, numeric IDs, or long opaque URL identifiers.

Known Express route templates are preferred. Fallback paths replace UUID, numeric, and opaque path segments with stable placeholders before persistence.

## Runtime behavior

The telemetry middleware is fail-open. It records after the response finishes and never changes the request outcome. PostgreSQL write failures are throttled to one warning per minute so telemetry cannot flood logs or take the API offline.

`X-Request-Id` is accepted when supplied, normalized to a bounded safe value, and otherwise generated by SkyCommand. The same value is returned in the response header and persisted for correlation.

## Dashboard contract

`GET /api/admin/api-telemetry/summary?days=7` requires `API_TELEMETRY_READ` and returns:

- total requests and success rate;
- client and server error counts;
- average, p95, and p99 duration;
- daily request/error and latency series;
- busiest normalized routes;
- application traffic distribution.

The Command Center renders four KPI cards, API traffic and latency charts with full-screen overlays, and a busiest-routes table.

## Retention

`API_TELEMETRY_RETENTION_DAYS` controls startup pruning and defaults to 30 days. The first implementation stores one row per request. Hourly rollups can be added later if traffic volume grows enough to justify aggregation.

## Deployment

Apply migration `00071__api_request_telemetry.sql` and seed `00072__api_telemetry_permissions_seed.sql`, restart the API, and sign in again so the new permission is present in the active session.

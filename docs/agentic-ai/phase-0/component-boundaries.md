# Phase 0 component boundaries

These boundaries finalize ownership for later implementation without adding executable Agent behavior.

| Component                        | Owns                                                                                                                                                                                                | Does not own                                                                                                                                                                                  |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/agents`                | Provider-neutral domain types, versioned contracts, validation helpers, authority/lineage value objects, and result/evidence normalization primitives                                               | Provider RPCs, credentials, business admission, Temporal orchestration, scheduler decisions, privileged host access, or autonomous execution                                                  |
| Agent Execution Service          | Authentication context construction, Project/Agent discovery, policy intersection, admission/idempotency, immutable snapshots, grants, run/session/read/cancel command boundaries, and audit intent | Provider reasoning/protocol, raw filesystem paths, client-asserted identity/permissions, direct provider sends, or replacement of existing capability services                                |
| Capability Authorization Service | Live root/run epoch checks, resource/parameter/data-release checks, effect receipts, and authorization of a governed capability invocation                                                          | Creating ungoverned Agent children, broad service identity substitution, provider session ownership, or replacing Browser/Tool/Workflow/Playwright dispatch                                   |
| Agent Runtime Supervisor         | Isolated cell/process lifecycle, lease/fence enforcement, credential-broker handoff, operation journal, event ingestion, reconciliation, watchdog/containment, and adapter invocation               | Authority expansion, Agent/project selection, delegation policy, schedule creation, result identity/status/usage invention, or direct control-plane/database credentials in the model runtime |
| Credential Broker                | Short-lived audience-bound Run/epoch grants, scoped MCP/API channel credentials, credential hashing/rotation, and revocation-aware renewal                                                          | Storing secrets in prompts, trusting model-supplied identity, broad reusable bearer tokens, authorizing outside the grant, or exposing provider credentials to the runtime                    |

## Boundary rules

1. SkyCommand is the sole admission authority. Every manual, workflow, scheduler, delegation, and future external entry path resolves through the same execution/authorization service.
2. The supervisor receives a pinned grant and context; it cannot widen authority or create independent work. Runtime adapters translate protocol and telemetry only.
3. Existing MCP → Assistant API → Temporal → Browser Worker → Playwright behavior remains the capability path. Capability authorization adds context and receipts without replacing that path.
4. The current privileged Host Agent remains a distinct infrastructure principal. It is not the Agent Runtime Supervisor and must not host model execution.
5. Canonical identity, lifecycle status, usage/cost availability, artifacts, and child-run completion are SkyCommand evidence. Provider/model output is a candidate and cannot overwrite those fields.
6. Phase 0 implements none of these services; it records the seams and contracts for later phases while execution remains disabled.
